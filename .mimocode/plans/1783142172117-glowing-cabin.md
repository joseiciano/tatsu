# Fix: opencode EEXIST in Docker container worktrees

## Problem

When opening a Docker container worktree with opencode, users see:
```
EEXIST: file already exists, mkdir '/workspace/.local/share/opencode'
```

## Root Cause

Three-step chain in `src/main/worktree-containers/worktree-containers.ts`:

1. **Line 245**: The host's opencode data directory (`~/.local/share/opencode` or macOS `~/Library/Application Support/opencode`) is bind-mounted into the container at the target path `/workspace/.local/share/opencode`. The `addExistingVolume` function creates this mount, which Docker materializes as a directory.

2. **Line 310**: The container environment sets `XDG_DATA_HOME=/workspace/.local/share`, so opencode resolves its data path to `/workspace/.local/share/opencode`.

3. **opencode's startup**: The `opencode-ai` npm package (installed at Dockerfile line 16) calls `fs.mkdirSync('/workspace/.local/share/opencode')` without `{ recursive: true }`. Since the bind mount already occupies that path, `mkdir` returns `EEXIST` (errno -17).

The directory exists *because Tatsu mounted it there*; opencode then fails trying to create the same directory.

## Fix

### File: `src/main/worktree-containers/worktree-containers.ts`

**Change in `addAgentAuthVolumes` (around lines 240–246)**:

Instead of mounting each agent's data/config/cache subdirectory individually under the XDG paths (which conflicts with `mkdir`), mount the **parent XDG directories** from the host when they exist. This way:

- The host's `~/.local/share` is mounted at `/workspace/.local/share` (the `XDG_DATA_HOME`)
- opencode's data lives at `$XDG_DATA_HOME/opencode` = `/workspace/.local/share/opencode` as a subdirectory of the mount, not the mount point itself
- `mkdir` either finds an existing subdirectory from the host or creates one cleanly inside the writable parent mount
- Same fix applies to cache (`XDG_CACHE_HOME`)

Concretely, replace lines 240–246 with logic that:

1. Mounts `hostDataHome` → `containerDataHome` (e.g. `~/.local/share` → `/workspace/.local/share`) when the host data home exists, **instead of** mounting the individual `opencode` subdirectory
2. Mounts `hostCacheHome` → `containerCacheHome` similarly
3. Preserves the existing config mount (read-only) and file-reference volumes unchanged, since those don't have the `mkdir` conflict
4. Adds dedup guard so the parent mount doesn't conflict with any existing volume targeting the same path

### File: `src/main/worktree-containers/worktree-containers.test.ts`

Update tests that assert the old per-app mount targets:

- **Lines 432–448** (`mounts existing local agent auth directories`): Change assertions from individual opencode subdirectory mounts to parent XDG directory mounts
- **Lines 479–492** (`does not mount the same macOS Opencode directory with mixed read-write modes`): Update to reflect the new parent mount strategy
- **Lines 588–609** (`passes read-only mode only for read-only auth mounts`): Update bind mount assertion strings

2. `pnpm test` — all tests pass (especially `worktree-containers.test.ts`)
3. Manual: create a Docker container worktree with opencode as the agent, open a terminal, run `opencode` — no EEXIST error
